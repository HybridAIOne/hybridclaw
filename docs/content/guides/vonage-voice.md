# Vonage Voice

HybridClaw's phone channel can use the Vonage Voice API as an alternative to
Twilio.

That means:

- Vonage handles speech-to-text (Google ASR) and text-to-speech (`talk`).
- HybridClaw receives one transcript per spoken turn over signed HTTPS
  webhooks — there is no websocket relay.
- The same gateway can handle inbound calls and place outbound calls through
  the Vonage Calls API.

Compared to Twilio ConversationRelay, the Vonage channel is strictly
turn-based: the caller speaks, Vonage posts the transcript, HybridClaw thinks
while the call stays parked and listening, and the finished reply is spoken
via a live-call NCCO transfer. Responses are not streamed word-by-word into
the call. If you want streamed speech and mid-sentence barge-in, prefer
[Twilio Voice](./twilio-voice.md).

## What You Need

- a Vonage account with a voice-capable number
- a Vonage Application with the Voice capability and signed callbacks enabled
- the application's private key and your account signature secret stored in
  HybridClaw's encrypted secret store
- a public `https://` base URL that Vonage can reach

Important:

- do not keep the private key or signature secret in plaintext config if you
  can avoid it
- do not rely on `localhost` or `127.0.0.1` for Vonage callbacks
- restart the gateway after changing Vonage voice config or secrets

## How The Channel Works

The flow is:

1. Vonage sends the inbound call to HybridClaw's answer webhook.
2. HybridClaw returns an NCCO: speak the greeting, then listen for speech.
3. Vonage posts the caller's transcript to the input webhook.
4. HybridClaw immediately parks the call (still listening) and runs the agent
   turn in the background, because Vonage cuts off slow webhook responses.
5. When the reply is ready, HybridClaw transfers the live call to a new NCCO
   that speaks the reply and listens again.
6. Call status events arrive on the event webhook; `completed` ends the
   session.

For outbound calls, `hybridclaw gateway voice call <number>` tells Vonage to
dial the destination and point the live call back at the same HybridClaw
answer webhook.

## Create The Vonage Application

In the [Vonage dashboard](https://dashboard.nexmo.com/) (or via the
Application API):

1. create an application with the **Voice** capability
2. generate the keypair and save the private key
3. enable **signed callbacks**
4. set the webhooks (with `POST` where offered):
   - answer URL: `https://voice.example.com/voice/answer`
   - event URL: `https://voice.example.com/voice/event`
5. link your voice-capable number to the application

Also note your account **signature secret** from the dashboard settings; it is
separate from the API secret and is what signs webhook JWTs.

If you changed `voice.webhookPath`, replace `/voice` with your configured
path. The input webhook (`<webhookPath>/input`) is generated by HybridClaw
inside NCCOs; you do not configure it in the dashboard.

## Minimum Config

Use either `/admin/channels` or `~/.hybridclaw/config.json`.

Minimal config:

```json
{
  "channelInstructions": {
    "voice": "This is a live phone call. Produce plain spoken text only."
  },
  "ops": {
    "gatewayBaseUrl": "https://voice.example.com"
  },
  "voice": {
    "enabled": true,
    "provider": "vonage",
    "vonage": {
      "applicationId": "your-vonage-application-id",
      "privateKey": "",
      "signatureSecret": "",
      "fromNumber": "+14155550123"
    },
    "relay": {
      "language": "en-US",
      "interruptible": true,
      "welcomeGreeting": "Hello! How can I help you today?"
    },
    "webhookPath": "/voice",
    "maxConcurrentCalls": 8
  }
}
```

Notes:

- `ops.gatewayBaseUrl` must be the public URL Vonage sees, not a local one.
- `voice.webhookPath` controls the base path for:
  - `<webhookPath>/answer`
  - `<webhookPath>/input`
  - `<webhookPath>/event`
- `voice.vonage.fromNumber` must be an E.164 number like `+14155550123`.
- `voice.relay.language` and `voice.relay.welcomeGreeting` apply to Vonage;
  `relay.ttsProvider`, `relay.voice`, and `relay.transcriptionProvider` are
  Twilio-only knobs and are ignored.
- `voice.relay.interruptible` maps to NCCO `bargeIn`, so callers can talk over
  the spoken reply to submit their next turn.
- leave `voice.vonage.privateKey` and `voice.vonage.signatureSecret` empty
  when you store the real values in the encrypted secret store.

## Store The Vonage Secrets

HybridClaw expects both Vonage secrets in the encrypted runtime secret store:

- `VONAGE_PRIVATE_KEY` — the application's RSA private key (PEM). A value with
  literal `\n` escapes instead of real newlines is accepted and normalized.
- `VONAGE_SIGNATURE_SECRET` — the account signature secret used to validate
  signed callbacks.

Local TUI or local web chat:

```text
/secret set VONAGE_SIGNATURE_SECRET your-signature-secret
```

For the multiline private key, prefer the admin console (`/admin/channels` →
`Voice` → `Vonage application private key`) or a SecretRef-backed config
value:

```json
{
  "voice": {
    "vonage": {
      "privateKey": {
        "source": "store",
        "id": "VONAGE_PRIVATE_KEY"
      },
      "signatureSecret": {
        "source": "store",
        "id": "VONAGE_SIGNATURE_SECRET"
      }
    }
  }
}
```

Important:

- HybridClaw rejects unsigned or invalidly signed Vonage webhooks, so voice
  will not work until the signature secret matches and signed callbacks are
  enabled on the application
- the voice runtime is safest after a gateway restart following secret changes

## Start And Verify

```bash
hybridclaw gateway restart --foreground
hybridclaw gateway status
hybridclaw gateway voice info
```

What you want to see:

- voice enabled with provider `vonage`
- application ID and from number configured
- private key and signature secret configured from the secret store
- a public answer webhook URL, not `localhost`

Expected gateway startup log:

```text
Voice integration started inside gateway
```

Common startup failures:

- `Voice integration disabled in config`
- `Voice integration disabled: Vonage credentials are incomplete`

## Test Calls

Inbound: call your Vonage number, wait for the greeting, and speak a short
question. Expect a pause while the agent thinks — the call stays listening,
and you can add to your question during the pause.

Outbound:

```bash
hybridclaw gateway voice call +4915123456789
```

The outbound command validates the number as E.164, checks the Vonage
credentials, refuses to dial if `ops.gatewayBaseUrl` still points at
`localhost`, and returns the Vonage call UUID and initial status.

## Troubleshooting

### Calls connect but the greeting never plays

- the answer webhook URL on the Vonage application does not match
  `ops.gatewayBaseUrl` + `<webhookPath>/answer`
- signed callbacks are disabled on the application, so HybridClaw rejects the
  webhook — check gateway logs for
  `Vonage voice webhook rejected: invalid signed-callback JWT`

### Signature validation fails

- the stored `VONAGE_SIGNATURE_SECRET` does not match the dashboard value
- the request body was rewritten by a proxy (the signed `payload_hash` pins
  the exact bytes Vonage sent)

### The agent answers but outbound `voice call` fails

- `VONAGE_PRIVATE_KEY` is missing, or is not the private key of the
  configured `voice.vonage.applicationId`
- Vonage caps outbound call creation at roughly 3 calls per second; retries
  are not queued
